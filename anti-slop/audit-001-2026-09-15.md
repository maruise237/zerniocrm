# Audit antislop 001 — 2026-09-15

Audit du projet ZernioCRM (interface Kamtech) selon les directives antislop
(https://github.com/miqdadbadjuber/anti-slop) : noyau `antislop.md` (règles R-01 à R-38)
+ compétences `antislop-ui`, `antislop-copywriting`, `antislop-code`, `antislop-human`,
`antislop-layoutmobile`.

Mode : **After** (audit d'un projet fini). Priorité = niveau de la règle :
Hard Gate → HIGH, Purpose-Gate → MEDIUM, Quality Locks → LOW.

Méthode de correction : un constat à la fois, validation (vitest + tsc + build) après chacun.

## Constats

### HIGH (Hard Gate)

**1. R-02 — Tirets cadratins (`—`) dans les textes visibles (~60 occurrences)**
Toasts, libellés, options de select, meta title/description, aides contextuelles,
prompt IA copiable, et 6 affichages de valeur vide (`return '—'` dans
campaigns/page.tsx, detail-view.tsx, invite-share.ts, timezone.ts, template-meta.ts).
Interdit sans exception par R-02. Remplacement : virgule, deux-points, parenthèses
ou phrase coupée ; placeholders de valeur vide → `-`.
(Fichiers : layout.tsx, settings, contacts + dialog, flows, templates + create-dialog,
campaigns ×3, team, auth/invite, page.tsx, ai-prompt.ts.)

**2. R-25 — Contraste texte AA échoué en mode clair**
`text-emerald-600` sur blanc = 3,77:1 et `text-amber-600` sur blanc = 3,19:1,
utilisés pour du petit texte (10–12 px) : contacts/page.tsx (×4), settings/page.tsx,
campaigns/create-dialog.tsx, components/alertes. Minimum AA : 4,5:1.
Correction calculée : `emerald-700` (5,48:1) et `amber-700` (5,02:1) en clair ;
le mode sombre passe déjà (`-400` : 10,3:1 et 11,9:1).
Preuve : scripts/contrast-audit.py (formule WCAG 2.x de antislop-human).

**3. R-32 — Focus supprimé sans remplacement sur les champs de saisie**
16 inputs avec `outline-none` et aucun indicateur de focus visible (settings,
templates, create-dialogs, page, contacts). Une seule input (clé API) a un
`focus:ring`. Correction : règle globale `:focus-visible` (outline 2 px `--ring`,
offset 2 px) dans globals.css, qui fournit un indicateur uniforme et visible
sur toute l'application, y compris les 16 champs concernés.

### MEDIUM (Purpose-Gate / compétences UI et code)

**4. Emoji décoratifs dans l'interface (UI skill, R-04/R-31)**
4 marques décoratives : `🛰` (option « Détection automatique », settings),
`🖼` (chip « En-tête », templates), `✓` (toast « Envoyé en direct », campagnes),
`⚠️` (note personnalisation, create-dialog). Le texte porte déjà le sens.
**Conservés avec raison écrite** : emoji du sélecteur de messages et réactions
(fonctionnels, contenu utilisateur), aperçus de type de message `🎤 📷 🎥 📎 📍 📞`
(convention WhatsApp réelle de l'app métier, marques pertinentes liées au contenu).

**5. antislop-code — Séparateurs décoratifs et narration dans les commentaires (~45)**
Bannières `// ── Titre ─────…` (flows, message-metadata, server/zernio, journal,
workspace, personalization, team/×3, api-client, whatsapp/interactive, db/schema,
flows/templates, campaigns/detail-view, page, contacts, team) et sections numérotées
`// 1. … ----` à `// 6. …` (whatsapp/interactive.ts), plus une narration orpheline
`// Step 2 :` (campaigns/create-dialog.tsx:270). Correction : une ligne simple sans
décoration ; le contenu informatif est conservé, le code n'est pas touché.

**6. antislop-human — Non-texte sous 3:1 en mode clair**
`--chat-presence` (vert « en ligne », point d'état réel) = 2,30:1 sur blanc ;
`--chat-border` (bordures d'inputs) = 1,26:1. Correction pragmatique : présence
assombrie à ~3:1 (oklch 0,72 → 0,62), bordure légèrement renforcée (0,92 → 0,87) ;
le résidu de bordure est couvert par l'indicateur de focus du constat 3.

### LOW (Quality Locks)

**7. R-27 (mineur) — Carte d'état WhatsApp sans état de chargement**
flows/page.tsx:349 : `if (isLoading) return null;` — la carte disparaît pendant le
chargement. Correction : petit texte « Vérification de l'état du canal… ».

**8. R-29/R-31/R-37 — Identité non consignée + primaire dormant**
`--primary`/`--ring` orange (oklch 35°) n'est utilisé que par 7 primitives shadcn
et l'anneau de focus, alors que l'accent réel de l'interface est le vert WhatsApp
(#25D366 / emerald) ; aucune raison de design n'est écrite nulle part.
Correction : aligner `--primary`/`--ring` sur un vert de marque respectant 3:1
(light : #16a34a ; dark : #4ade80) et créer `DESIGN.md` (une page : palette,
typographie DM Sans/Manrope + raisons, motif bulle de chat, dials
ENERGY 1 / RHYTHM 2 / MOTION 1) pour verrouiller l'identité existante.

## Constats vérifiés sans violation (preuves)

- R-03 Mobile : layout mobile-first natif (barre d'onglets, `.touch-target` 44 px,
  inputs 16 px anti-zoom iOS, shell `overflow:hidden` + scrolls internes, largeurs
  fluides `md:`/`lg:`) — aucun débordement horizontal codé.
- R-15 CTA : libellés spécifiques (« Envoyer maintenant », « Créer la campagne »,
  « Connecter votre compte WhatsApp ») ; aucun « Get Started/Learn More ».
- R-16/R-36 : aucun buzzword ni fausse statistique (grep élargi négatif).
- R-17/R-18/R-38 : pas de faux chiffres, faux témoignages, fausses personnes ;
  `example.com` uniquement en tests et en placeholder honnête d'URL.
- R-21/R-34 : toggle clair/sombre fonctionnel (settings + script anti-flash) ;
  les deux jeux de tokens existent.
- R-24/R-26 : toutes les routes de navigation existent ; aucun `href="#"` ;
  formulaires et boutons câblés (230 tests verts, API réelles).
- R-27 : états chargement/vide/erreur présents sur Contacts, Templates, Flows,
  Campagnes (constat 7 = un seul trou mineur).
- R-28 : pas de FAQ. R-33 : aucun script de patch CSS/fichier dans le dépôt.
- R-05/R-30 : application métier (inbox), structure dictée par le contenu ;
  l'inspiration « inbox WhatsApp » est le produit demandé, pas un clone déguisé.
- R-06 : DM Sans (corps) + Manrope (titres), hors roster par défaut IA ;
  raisons à consigner dans DESIGN.md (constat 8).

## Suivi de correction (2026-09-15, même journée)

Les 8 constats ont été corrigés un par un, chacun validé par
`vitest run` (230/230) + `tsc --noEmit` (0 erreur) ; `next build` exécuté
aux étapes 3, 8 et à la clôture. Un commit unique livre l'ensemble.

1. **R-02 (fait)** : 13 fichiers + prompt IA + 4 messages d'erreur API.
   Remplacements : deux-points, virgule, parenthèses `(Détail)`, point,
   point médian `·` pour les séparateurs de titre. Placeholders `return '—'`
   → `return '-'` (6 endroits). Test ai-prompt mis à jour
   (« 3 boutons maximum »). Reste : uniquement commentaires de code (hors
   périmètre R-02) et exemples de tests.
2. **R-25 (fait, périmètre élargi)** : `text-emerald-600`→`700`,
   `text-amber-600`→`700`, `text-red-500`→`text-red-600 dark:text-red-400`
   (hover et variantes /80 gérées), `text-sky-600`→`700`,
   `text-indigo-500`→`600 dark:400`, tuiles d'icônes `-500`→`-600 dark:-400`,
   StatCards campagne → `-700 dark:-400`. Preuve : scripts/contrast-audit.py.
3. **R-32 (fait)** : règle `:focus-visible` globale non-layered dans
   globals.css (outline 2 px `--ring`, offset 2 px), prime sur `outline-none`.
   Échap = Radix Dialog natif ; Tab = ordre DOM.
4. **Emoji décoratifs (fait)** : `🛰 🖼 ✓ ⚠️ ℹ️` retirés. Conservés avec raison :
   picker d'emoji, réactions, aperçus `🎤 📷 🎥 📎 📍 📞` (convention WhatsApp
   du produit, marques liées au contenu).
5. **Commentaires (fait)** : ~60 runs décoratifs (`──`, `---`) convertis en
   lignes simples via scripts/fix-comment-banners.py (commentaires uniquement,
   zéro code modifié) ; sections numérotées de whatsapp/interactive.ts
   dénumérotées ; `// Step 2 :` réécrit ; bloc api-client décoré déchargé de
   ses 2 séparateurs (les 3 lignes informatives restent).
6. **Non-texte (fait)** : `--chat-presence` clair 0,72 → 0,62 (2,30 → 3,29:1) ;
   `--chat-border` clair 0,92 → 0,87 (1,48:1, résidu assumé et documenté,
   identification couverte par le focus R-32).
7. **R-27 (fait)** : la bannière d'état WhatsApp affiche
   « Vérification de l'état du canal WhatsApp… » au lieu de disparaître.
8. **Identité (fait)** : `--primary`/`--ring` clair `#15803d` (vert de marque
   green-700, 5,0:1), sombre `#4ade80` + texte `#052e16` (8,6:1) ; les bulles
   sortantes `color-mix(primary…)` deviennent vertes, conformes à la métaphore
   WhatsApp. `DESIGN.md` créé à la racine (dials ENERGY 1 / RHYTHM 2 /
   MOTION 1, palette, typographies et raisons, gestes).
